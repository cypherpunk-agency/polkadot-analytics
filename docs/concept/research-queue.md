# The research queue

Questions this project has opened and not yet answered.

**Why this file exists.** Almost every task here turns up questions it will not answer, and those
decay fast — an unrecorded question is either re-derived later at full cost, or silently dropped
along with whatever it would have unlocked. Keeping them in one place is what lets research run in
parallel with delivery instead of behind it.

A question that gets **answered** leaves here and goes into `docs/platform/`, `CLAUDE.md`'s facts
list, or `docs/decisions/` — see the `research-and-build` skill, §4. This file is only for what is
still open.

Two kinds, and they route differently:

- **BLOCKING** — something cannot be built correctly until this is settled. The "blocks" column
  says what is stalled.
- **OPENING** — nothing is stalled, but a capability becomes reachable if it is answered. These
  are the ones that get lost, and they are often where the leverage is.

Cost is a rough order of magnitude for the *research*, not the build.

## Two rules about the ids, both learned the hard way

**`B<n>` here is not `B<n>` in the plan.** This file's B-series is *blocking questions*;
`docs/concept/plan.md`'s B-series is *Wave B build items*. They are independent and they collide.
Always write "research queue B5" rather than bare "B5" when crossing between the two documents —
the existing cross-references do, and a bare label has already caused one round of confusion.

**Ids are append-only and are never reused.** Three agents appending in parallel on 2026-08-20
produced two separate O23–O26 blocks, and the collision outlived the renumbering that fixed it by
a day, because the *note about* the collision was left behind in a row that no longer collided.
A closed question's number stays retired. Gone for good: **B1, B3, B4, B7, O3, O8, O9, O26, O27,
O28, O35, O39, O44, O46, O57**.
**Next free id: B10, O83.** One table per kind, in numeric order, so a duplicate is visible rather
than argued about — and if you add a row, bump that line.

It happened again on 2026-08-21, and this is what the rule is for: seven agents worked in parallel
with `docs/**` frozen, and four of them drafted queue rows into scratch files. Two independently
numbered from **O41**, which was already taken; one numbered from O50, which was right. Everything
was renumbered at merge and the questions themselves survived unharmed. **If you cannot write to
this file, write the question down anyway and let the merge assign the id** — a question with the
wrong number is a renumbering, a question nobody wrote down is gone.
